# Kontur — учебная симуляция производственного планирования

Kontur — русскоязычная детерминированная учебная симуляция для планировщика и руководителя участка. Передайте спрос, сравните предусмотренные варианты производства, зафиксируйте заявки на персонал, получите два явных подтверждения, затем отработайте поломку станка и отсутствие работников в одной цепочке версий.

**Не производственная система:** нет оптимизатора, подключения к MES, серверной части, облачного сервиса, учётных записей и телеметрии. Переключение ролей имитирует разделение ответственности, а не аутентификацию. Расчётные результаты — не наблюдения на заводе и не свидетельство проведённого пилота.

## Быстрый запуск в Windows

Понадобятся Node.js **24.19.0**, npm **11.17.0**, поставляемые `package.json` и `package-lock.json`, а также актуальный браузер. Откройте PowerShell **в корне проекта**, рядом с `package.json`. Для установки нужен доступ к реестру пакетов или достаточный локальный кеш; первая установка без сети не гарантируется.

Выполняйте следующую команду только после успешного завершения предыдущей:

```powershell
node --version
npm.cmd --version
npm.cmd ci --strict-peer-deps --ignore-scripts --include=dev --no-fund
npm.cmd run build
npm.cmd run serve
```

Откройте **http://127.0.0.1:4173/** — локальную демонстрацию на localhost. Не закрывайте терминал сервера. Презентация доступна по адресу **http://127.0.0.1:4173/slides.html**. Для остановки сервера нажмите **Ctrl+C**.

- `ci` использует lockfile без обновления и отключает скрипты жизненного цикла зависимостей. Команда заменяет существующий `node_modules`; не запускайте её во время чужой проверки.
- Поставляемые npm-скрипты вызывают Node через **локальные точки входа пакетов**, например `node node_modules/vite/bin/vite.js build`. Это обходит замеченную в Windows проблему оболочек запуска в путях с `p&g`. Используйте `npm.cmd`, а не оболочки Vite/Vitest напрямую или `npx`; не меняйте глобальные настройки оболочки.
- `serve` раздаёт существующий `dist` на **127.0.0.1:4173**, без пересборки и выбора другого порта. После изменения продукта соберите его заново. Если порт занят, остановите только свой сервер или договоритесь с владельцем; не завершайте посторонний процесс.
- Работа **без сети** означает, что подготовленная производственная сборка работает через локальный HTTP без удалённых ресурсов. Это не означает установку зависимостей, браузера или пересборку без сети на неподготовленном компьютере. Не открывайте `dist/index.html` через `file://`.
- Локальный статический HTTP-сервер лишь раздаёт файлы демонстрации. Это не серверная часть приложения и не гарантия безопасности публичного размещения.

Команды сверены с поставляемыми скриптами. При обновлении документации зависимости не переустанавливались, а параллельно проверяемый кандидат не пересобирался.

## Как читать числа

- Объёмы указаны в **тысячах лезвий**; выполнение заказа засчитывается только после PACK. Внутренние `A/B/C` соответствуют исходным продуктам `А/Б/В`.
- Горизонт — четыре смены по **630 рабочих минут**. Табличное время `t` исключает перерывы и передачу смены; это не прошедшее календарное время.
- Эффективная скорость каждого станка — `nominal × 0.85 / 1000` тысяч лезвий в минуту при наличии входного материала. Коэффициент 0.85 применяется один раз к номинальной скорости каждого станка, а не как повторная потеря материала по маршруту.
- Запасы — отдельные очереди перед каждой операцией, включая внутреннее незавершённое производство (WIP). Начальные запасы вводятся один раз; следующие смены и версии с событиями наследуют остатки. Готовый нераспределённый выпуск PACK учитывается отдельно.
- Заявки S1/S2 фиксируются до модельного **D 12:00**; S3/S4 остаются прогнозами. Пик — одновременная потребность, а не заявленная численность.
- Физические ошибки блокируют согласование. Для предупреждений по срокам и квотам нужно явное обоснование, а не скрытое изменение объёмов, исходных сроков или персонала. Новое обещание не отменяет исходное обязательство.
- В v1.3/D3 реестр `orderOrigins` сохраняет исходные объём и срок каждого принятого ID на всю цепочку версий. Удаление или переименование заказа не позволяет заново определить эти значения для прежнего ID. Реестр не добавляет спрос: расчёт учитывает только заказы текущего плана.

Предусмотренный общий сценарий проверен через публичный API предметной области: фиксированные заявки **28/41**, фактическая доступность S2 после отсутствия — **39**, итоговые пики — **28/39/41/32**, выполнены **12/12** обязательных работ на станках, дефицит к исходному сроку равен нулю **по всем шести заказам**. Это результат конкретного учебного сценария с указанными корректировками, а не гарантия для пользовательских заказов, произвольных событий, минимальной численности или реального производства. См. [контрольные точки демонстрации](docs/DEMO_GUIDE.md#common-scenario-checkpoints).

## Сохраните результат перед выходом

Перед перезагрузкой, восстановлением или сбросом нажмите **«Экспорт JSON»** в **«Паспорт сценария»**. Файл `kontur-v<revision>-<phase>.json` содержит историю процесса и текущий расчёт с полной точностью конечных чисел. Одинаковое состояние даёт побайтово одинаковый экспорт; это не подтверждение происхождения цифровой подписью.

Состояние хранится только в текущем сеансе страницы. Постоянное хранение и импорт/восстановление из JSON не гарантируются. **«Восстановить сценарий»** действует сразу; **«Сбросить»** запрашивает подтверждение. Обе команды удаляют правки сеанса, обещания, события, заявки, подтверждения и историю и возвращают исходные шесть заказов на D 11:00. При этом пользовательская история `orderOrigins` очищается, а реестр заново содержит только исходные шесть заказов. Если экспорт ещё не сохранён, отмените сброс кнопкой **«Отмена»**.

Выбор **темы** сохраняется отдельно в браузере, если доступно локальное хранилище. Первый запуск — в светлой теме. Это не сохраняет сам производственный план. Презентация всегда светлая, в том числе при тёмной системной теме.

[Исходный пакет подтверждений](evidence/package.json) и `reviews/FINAL.md` относятся к историческому релизу до обновления интерфейса, а не автоматически к новым файлам. Команды тестов и проверки покрытия — воспроизводимые инструкции, а не заявление о 100% модульном покрытии всего интерфейса.
